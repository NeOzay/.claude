# Migrer le registre de dette vers la version 3

Cette note accompagne la version 3 de la définition `technical-debt`. L'avertissement de péremption
de `list-dir validate` la nomme à tout registre semé dans une version antérieure. Elle reste en
place quand plus aucun registre ne porte l'ancienne version : une note par version, dans l'ordre,
dit ce que chaque saut demande.

La même migration fait passer les quatre contrats de la dette :

| Registre | Version d'avant | Version d'après |
|---|---|---|
| `technical-debt` | 2 | 3 |
| `technical-debt`, patron `review` | 1 | 2 |
| `technical-debt-solde` | 1 | 2 |
| `technical-debt-ecarte` | 1 | 2 |

La version d'un registre est le champ `version` de son `.list/contract.toml`, et celle de son
patron, le champ `version` de `.list/patrons/review.toml`. Un registre qui porte déjà celle d'après
n'a rien à faire ici ; un registre plus ancien que celle d'avant se rattrape d'abord par `reseed` et
`migrate`, sans cette procédure.

Un registre `technical-debt` en version 2 dit d'où vient chaque dette dans un seul champ en texte
libre, `source`. La version 3 le remplace par `chantier` et `reference`, et ajoute `severite` et
`pin` ([Ce qu'une entrée porte](../../../references/dette.md#ce-quune-entrée-porte)). Cette note
dit comment y amener un registre existant, dans n'importe quel projet.

Le partage est celui de tout le pipeline. Les commandes font la structure : `reseed` rattrape le
contrat, `migrate` pose les champs neufs, `fill` écrit la valeur commune. L'agent
`migrateur-de-liste` reporte `source` dans `chantier` et `reference`, entrée par entrée, selon la
consigne ci-dessous. La garde vérifie ce qu'il a écrit. L'utilisateur tranche ce qui reste au
Marqueur. Un report confié à la main d'un modèle sans garde ne laisse rien voir de ses erreurs : une
valeur fausse s'écrit exactement comme une juste.

**Tout se rejoue.** `reseed` d'un contrat à jour n'écrit rien, `migrate` ne touche pas un élément
conforme, `fill` saute ce qui n'est plus au Marqueur. Une migration interrompue reprend au premier
geste, sans rien défaire.

**`migrate` met chaque entrée en conformité avec le contrat entier**, pas seulement avec ses champs
neufs. Un champ ou une section facultatifs qu'une entrée ne porte pas y sont posés au Marqueur —
`reviewed`, `category`, `## Assumé` —, et des sections dans le désordre reprennent l'ordre du
contrat. Aucun texte ne change, mais le diff de `migrate` touche plus de lignes que les champs
neufs : c'est pourquoi la structure se committe seule, avant l'agent, et que la garde ne lit que
le diff qui suit.

## La procédure

`$T` vaut `.claude/implementation/todo`, à la racine du projet. Chaque geste part d'un arbre propre
sur les trois listes.

1. **Noter le commit d'avant** — la consigne de l'agent lui fait lire le contrat d'avant à ce
   commit :

   ```bash
   AVANT=$(git rev-parse HEAD)
   ```

2. **Les listes de sortie**, `-solde` et `-ecarte` : `reseed` puis `migrate`, et rien d'autre. Leurs
   champs neufs sont facultatifs et restent au Marqueur : leurs entrées ne se migrent pas, et
   `source` n'y est pas déprécié.

   ```bash
   for l in technical-debt-solde technical-debt-ecarte; do
     list-dir reseed "$T/$l"
     list-dir migrate "$T/$l" --dry-run
     list-dir migrate "$T/$l"
     list-dir validate "$T/$l" --filled
   done
   ```

3. **La structure du registre** : le contrat, les champs neufs, la sévérité commune.

   ```bash
   list-dir reseed "$T/technical-debt"
   list-dir migrate "$T/technical-debt" --dry-run
   list-dir migrate "$T/technical-debt"
   list-dir fill "$T/technical-debt" severite inconnue --all
   ```

   `migrate` pose `pin` à `false` et les trois autres champs au Marqueur. `inconnue` dit qu'aucune
   sévérité n'a été jugée : la prochaine `/debt-review` la remplace. Le compte des deux commandes
   suivantes doit être égal :

   ```bash
   list-dir list "$T/technical-debt" | wc -l
   list-dir list "$T/technical-debt" --where severite=inconnue | wc -l
   ```

4. **Committer la structure, et noter ce commit** — la garde lit le diff de l'agent depuis lui :

   ```bash
   STRUCTURE=$(git rev-parse HEAD)
   ```

5. **Lancer `migrateur-de-liste` par lots d'environ trente entrées**, avec la consigne ci-dessous.
   Un lot prend les entrées dont l'un des deux champs est encore au Marqueur :

   ```bash
   { list-dir list "$T/technical-debt" --where 'chantier=<À REMPLIR>'
     list-dir list "$T/technical-debt" --where 'reference=<À REMPLIR>'; } | sort -u | sed -n 1,30p
   ```

   Un lot plus grand dépasse ce qu'un petit modèle tient sans sauter d'entrée. Un lot interrompu se
   relance tel quel : ce que l'agent a déjà posé ne sort plus de cette commande.

6. **Confronter le rapport** : chaque ligne `posé` cite le texte de `source` qui établit la valeur.
   Une valeur que sa citation ne justifie pas se corrige à la main, et se signale.

7. **Passer la garde** (plus bas). Elle doit sortir en 0.

8. **Vérifier la complétude** :

   ```bash
   list-dir validate "$T/technical-debt" --filled
   ```

   Elle nomme les entrées que l'agent a laissées au Marqueur. L'utilisateur tranche chacune, et la
   valeur s'écrit par `list-dir fill "$T/technical-debt" <champ> '<valeur>' --id <id>`. Puis
   committer.

## La consigne donnée à `migrateur-de-liste`

Le prompt de l'agent est ce bloc, ses trois valeurs entre chevrons remplacées : la racine du projet
en chemin absolu, le commit `$AVANT` et les `id` du lot.

```
Racine du dépôt : <racine absolue>
Liste : <racine absolue>/.claude/implementation/todo/technical-debt
Champs à remplir : chantier, reference. Champ où lire leur valeur : source.

Contrat d'après : list-dir contract <liste>
Contrat d'avant : git -C <racine> show <AVANT>:.claude/implementation/todo/technical-debt/.list/contract.toml

Lot : <id, un par ligne>

Slugs admis pour chantier — un par ligne, à vérifier avant d'écrire :
find <racine>/.claude/implementation/done -maxdepth 1 -name '*.md' ! -name '*.audit.md' ! -name '*.brief.md' ! -name '*.plan.md' -printf '%f\n' | sed -E 's/^[0-9]{4}-[0-9]{2}-[0-9]{2}-//; s/\.md$//'

chantier — la première règle qui s'applique décide :
1. source commence par « hors chantier » ou « audit hors chantier », sans tenir compte de la
   casse : « Hors chantier ».
2. source commence par « chantier » ou « Identifié par », suivi d'un nom, entre accents graves ou
   non : ce nom, accents graves retirés, et préfixe daté AAAA-MM-JJ- retiré s'il en porte un.
   « chantier 2026-08-31-champs-preremplis » donne « champs-preremplis ».
3. Toute autre forme : laisser au Marqueur.
Un nom absent des slugs admis : laisser au Marqueur. Un autre nom cité plus loin dans source ne
compte pas : seul le premier décide.

reference — la première règle qui s'applique décide :
1. source cite des R<n> : tous ceux qui se rapportent au chantier retenu, dans l'ordre où ils
   apparaissent, séparés par « , ». « R1 et R3 » donne « R1, R3 ». Une plage reste une plage :
   « R5 à R8 » donne « R5 à R8 ». Les R<n> écrits après le nom d'un autre chantier (« élargi par
   `revue-dette`, R14 ») se rapportent à lui : ils n'entrent pas.
2. Sinon, le premier lieu cité, dans cet ordre de priorité :
   - une étape (« étape 7 », « constat de l'étape 9 ») : « Étape <n> » ;
   - une session (« en session 2 ») : « session <n> » ;
   - le journal du suivi (« journal du suivi », « Journal de décisions du Suivi ») : « journal du
     Suivi » ;
   - une réserve du relecteur de plan (« réserve Q2 du relecteur de plan ») : « relecture du Plan,
     Q<n> » ;
   - un hors-périmètre (« hors-périmètre assumé ») : « Hors-périmètre du Brief » ;
   - la clôture ou son audit, sans R<n> (« réserve de forme de l'audit de clôture ») : « Clôture ».
3. Sinon : « Non précisée ». C'est la seule valeur de repli, et elle ne s'écrit que dans ce cas.

Un hash de commit, un chemin de fichier ou une date cités dans source ne sont ni un chantier ni
une référence.
```

La consigne ne décrit que les formes de `source` que le pipeline a écrites. Une autre forme laisse
l'entrée au Marqueur, et l'utilisateur la tranche au geste 8 : l'agent ne la devine pas.

## La garde

La garde vérifie ce que l'agent a écrit, sans relire les entrées. Elle se lance avant le commit de
l'agent, depuis la racine du projet, et sort en 1 au premier défaut nommé :

```bash
bash -s -- "$T/technical-debt" .claude/implementation/done "$STRUCTURE" <<'GARDE'
set -euo pipefail
liste=$1 archives=$2 structure=$3

slugs=$(find "$archives" -maxdepth 1 -name '*.md' ! -name '*.audit.md' ! -name '*.brief.md' \
  ! -name '*.plan.md' -printf '%f\n' | sed -E 's/^[0-9]{4}-[0-9]{2}-[0-9]{2}-//; s/\.md$//')
[ -n "$slugs" ] || { echo "garde : aucun suivi archivé dans $archives" >&2; exit 1; }

chantiers=$(list-dir list "$liste" --sort chantier | cut -d' ' -f2- | sort -u)
[ -n "$chantiers" ] || { echo "garde : $liste ne rend aucune entrée" >&2; exit 1; }
hors=$(grep -vxF -e 'Hors chantier' -e '<À REMPLIR>' -f <(printf '%s\n' "$slugs") \
  <<<"$chantiers" || true)
[ -z "$hors" ] || { printf 'garde : chantier hors des slugs admis : %s\n' "$hors" >&2; exit 1; }

forme='R[0-9]+( à R[0-9]+)?(, R[0-9]+( à R[0-9]+)?)*|Étape [0-9]+|session [0-9]+'
forme+='|journal du Suivi|relecture du Plan, Q[0-9]+|Hors-périmètre du Brief|Clôture'
forme+='|Non précisée|<À REMPLIR>'
mal=$(list-dir list "$liste" --sort reference | cut -d' ' -f2- | sort -u \
  | grep -vxE "$forme" || true)
[ -z "$mal" ] || { printf 'garde : reference hors des formes de la consigne : %s\n' "$mal" >&2; exit 1; }

diff=$(git diff -U0 "$structure" -- "$liste" | grep -E '^[-+]' | grep -vE '^(\+\+\+|---) ' || true)
[ -n "$diff" ] || { echo "garde : aucun changement depuis $structure" >&2; exit 1; }
autre=$(grep -vE '^-(chantier|reference) = "<À REMPLIR>"$|^\+(chantier|reference) = ".+"$' \
  <<<"$diff" || true)
[ -z "$autre" ] || { printf 'garde : ligne hors des champs migrés :\n%s\n' "$autre" >&2; exit 1; }

echo "garde : $(list-dir list "$liste" | wc -l) entrées, $(grep -c '^+' <<<"$diff") valeurs posées, conformes"
GARDE
```

Ce qu'elle contrôle, et pourquoi chaque contrôle est là :

- **Chaque `chantier` est un slug de `done/` ou « Hors chantier »**, ou encore au Marqueur. Un nom
  hors de cet ensemble ne regroupe rien sous `--sort chantier`, et ne mène à aucun Chantier.
- **Chaque `reference` a l'une des formes de la consigne.** Une forme libre veut dire que l'agent a
  paraphrasé au lieu d'appliquer une règle.
- **Le diff depuis `$STRUCTURE` ne touche que des lignes `chantier` et `reference`**, d'un Marqueur
  à une valeur. Une autre ligne changée est une entrée réécrite au-delà des champs migrés : la
  migration s'arrête là.
- **Un contrôle qui n'a rien examiné échoue** : aucun slug, aucune entrée, aucun diff. Une garde
  muette sur une entrée vide passerait pour une garde qui a tout vu.

Elle ne dit pas qu'une valeur est la bonne : un slug admis peut être le mauvais. C'est le rôle de
la confrontation du rapport, au geste 6.
