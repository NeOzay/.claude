# Plan — lexique global et local

Brief : `.claude/implementation/lexique.brief.md` (validé, `execution = "direct"`).

## Contexte

Aucun terme n'a aujourd'hui de sens verrouillé. « gabarit » a porté deux sens jusqu'à ce que le
chantier `2026-09-20-deux-sens-de-gabarit` baptise « patron » le moule de `derive`, après coup.
Le chantier livre deux lexiques, chacun un tableau Markdown `terme | définition courte | lien` :
le global `~/.claude/LEXIQUE.md` et le local `<projet>/.claude/LEXIQUE.md`. Ils sont chargés
automatiquement après un fichier d'instructions importé par `CLAUDE.md`. Une commande liste les
termes réservés avec leur niveau et refuse les redéfinitions. Le lexique global est amorcé avec des
termes tirés de `gabarit`, `list-dir` et `implementation-tracker`.

**Rappel du brief** :
- **critères** : import des instructions puis des lexiques ; tableau à trois colonnes avec un lien
  par ligne ; termes proposés puis validés un à un ; lexique local en contexte sans action ;
  commande qui liste et sort en erreur sur une redéfinition ou un doublon ; tests, ruff et
  basedpyright propres ;
- **hors-périmètre** : aligner la prose des trois skills ; un niveau de lexique propre aux skills ;
  des termes tirés d'autres skills ;
- **signaux de dérive** : le global gonfle (terme non employé par une skill globale, ou définition
  de plus d'une phrase) ; le diff touche la prose de `gabarit`, `list-dir` ou
  `implementation-tracker` ; un lexique apparaît dans `skills/<nom>/`.

**Incertitudes du brief, levées ici** :
- **Chargement du lexique local** : un hook `SessionStart` dans `~/.claude/settings.json`
  (valable dans tous les projets) lance `lexique session`. La commande imprime
  `$CLAUDE_PROJECT_DIR/.claude/LEXIQUE.md`, que Claude Code verse dans le contexte. `CLAUDE.md`
  n'est pas dans le prompt système : il arrive en rappel système dans le premier message. La
  sortie des hooks `SessionStart` arrive après lui, comme on l'observe dans la session qui a
  produit ce plan (le rappel d'outillage suit le contenu de `CLAUDE.md`). L'étape 3 vérifie
  explicitement cet ordre. Le `grep` du critère 1 ne peut montrer que l'import des instructions et
  du global : le chargement local se constate à l'étape 3.
  `SessionStart` se déclenche aussi à la reprise et après compaction : le lexique local survit à
  un compactage.
- **Nom et emplacement** : c'est la skill-outil `skills/lexique/`, arbitrée avec l'utilisateur.
  Elle porte la commande, les instructions et la procédure d'ajout d'un terme, mais **aucun
  terme** : les termes vivent uniquement dans les `LEXIQUE.md`. Ce choix suit la convention « une
  commande globale est déclarée par une skill »
  (`skills/skill-convention/references/commandes-locales.md`).

## Arborescence visée

```
~/.claude/
├── CLAUDE.md             + @skills/lexique/instructions.md, puis @LEXIQUE.md
├── LEXIQUE.md            | Terme | Définition | Lien |
├── settings.json         + SessionStart → lexique session
├── bin/lexique           → ../skills/lexique/scripts/lexique-cli.py
└── skills/lexique/
    ├── SKILL.md          proposer, ajouter, modifier ou retirer un terme ; vérifier
    ├── instructions.md   règles d'emploi, chargées à chaque session
    ├── ruff.toml, pyrightconfig.json   copies de celles de skills/gabarit/
    └── scripts/
        ├── lexique-cli.py        point d'entrée, sans logique métier
        ├── lexique.py            lecture, fusion, contrôles
        └── tests/                conftest.py + un fichier par sujet
```

## Étapes

### 1. Bibliothèque et commande `lexique`

Écrire `skills/lexique/scripts/lexique.py`, en stdlib seule, puisque le hook tourne sous le
`python3` du PATH :
- `lire(chemin, niveau) -> Result[list[Terme]]` : le fichier peut porter de la prose, mais un seul
  tableau, dont l'en-tête est exactement `| Terme | Définition | Lien |`. Chaque ligne a trois
  cellules non vides, et la cellule `Lien` contient un lien Markdown `[…](…)`. Un fichier absent
  donne une liste vide.
- `controler(global_, local) -> list[Constat]` : fonction pure qui relève les doublons à
  l'intérieur d'un niveau et les termes locaux déjà réservés au global. La comparaison se fait après
  `casefold` et normalisation des espaces, puisqu'un terme peut compter plusieurs mots.
- Racine globale : localisée depuis l'emplacement du script (la skill est dans
  `<racine>/skills/lexique/`), jamais par une constante (`OUTILLAGE.md`).

`lexique-cli.py` fournit deux sous-commandes :
- `lexique liste [--projet DIR]` (défaut : le répertoire courant) : imprime `niveau  terme  lien`
  pour chaque terme, global d'abord. Codes de sortie : 0 conforme ; 1 constat, un par ligne sur
  stderr ; 2 erreur d'appel. Mêmes conventions de code que `gabarit`.
- `lexique session` : le projet est `$CLAUDE_PROJECT_DIR`, ou le répertoire courant à défaut.
  Sans lexique local, rien n'est imprimé. Sinon, un en-tête (« Lexique local de <projet> ») suivi du
  fichier tel quel, puis, en cas de constat, une alerte qui nomme les termes en conflit. **Sortie 0
  dans tous les cas** : un rappel ne bloque pas le démarrage (précédent :
  `hooks/outillage-rappel.sh`).

Poser `skills/lexique/ruff.toml` et `skills/lexique/pyrightconfig.json`, copies de celles de
`skills/gabarit/`. Sans eux, basedpyright vérifie en mode par défaut. `Result` est redéfini
localement, puisque le module n'utilise que la stdlib.

Tests (`scripts/tests/`) sur des arborescences temporaires : format accepté ; en-tête faux ; ligne
à deux cellules ; lien absent ; doublon global ; doublon local ; terme local réservé au global (y compris en
variante de casse ou d'espaces) ; fichier local absent ; `session` silencieux sans lexique ;
`session` en code 0 malgré un conflit. Créer le lien `bin/lexique`, relatif et exécutable, que
`scripts/sante_skills.py` contrôle.

Ajouter `skills/lexique/scripts` aux `extraPaths` du `pyrightconfig.json` racine : il couvre
`skills` et liste chaque dossier de scripts de skill. Les linters se lancent à la racine et se
comparent à la base (`OUTILLAGE.md`).

**Vérification** :


### 2. Instructions, skill, lexique global vide et chargement par `CLAUDE.md`

- `skills/lexique/instructions.md`, une quinzaine de lignes puisqu'il est chargé à chaque session.
  Il pose les règles suivantes :
  - un terme défini ne s'emploie que dans sa définition ; pour un autre sens, prendre un autre mot ;
  - si l'utilisateur emploie un terme hors de sa définition, **le lui signaler** (le terme, sa
    définition, le sens apparent) sans reformuler d'office ;
  - un terme du global ne se redéfinit jamais en local, et un terme n'est défini qu'une fois ;
  - aucun terme n'entre ni ne change dans un `LEXIQUE.md` sans l'accord explicite de
    l'utilisateur : l'agent propose ;
  - le global reste minimal : n'y entre qu'un concept employé par une skill globale, avec une
    définition d'une phrase ;
  - l'état des réservations s'obtient par `lexique liste`.
- `skills/lexique/SKILL.md`. Déclencheurs : proposer, ajouter, modifier ou retirer un terme ;
  amorcer un lexique local ; vérifier un lexique. Procédure : `lexique liste` pour voir les
  réservations, proposer la ligne, obtenir l'accord, écrire, relancer `lexique liste`. Prose
  conforme à `skills/skill-convention/references/prose.md`.
- `LEXIQUE.md` à la racine : une phrase qui renvoie aux instructions, puis l'en-tête du tableau,
  sans ligne.
- `CLAUDE.md` : ajouter `@skills/lexique/instructions.md` puis `@LEXIQUE.md` après `@RTK.md`.
- `skills/skill-convention/SKILL.md`, table « Où est chaque convention » : ajouter une ligne
  « Sens des mots | `LEXIQUE.md`, [lexique](../lexique/SKILL.md) | on emploie, propose ou définit
  un terme ». Cette skill n'est pas l'une des trois dont la prose est hors-périmètre.

**Vérification** :
```bash

lexique liste; echo "sortie $?" # 0, aucune ligne
/home/debian/.claude/.venv/bin/python scripts/check_pipeline.py
```

### 3. Hook `SessionStart` du lexique local

Ajouter à `~/.claude/settings.json`, sous `SessionStart`, une entrée **à côté** de celle de
`sante_skills.py` :
`python3 $HOME/.claude/skills/lexique/scripts/lexique-cli.py session`. L'appel passe par un
chemin et non par la commande nue, parce que le hook ne dépend pas du `PATH`, comme
`sante_skills.py`.

**Vérification** :
```bash
d=$(mktemp -d) && mkdir $d/.claude && printf '| Terme | Définition | Lien |\n|---|---|---|\n| essai | Un terme local. | [x](x) |\n' > $d/.claude/LEXIQUE.md
CLAUDE_PROJECT_DIR=$d python3 skills/lexique/scripts/lexique-cli.py session   # imprime le lexique
```
Puis l'utilisateur ouvre une session neuve (`claude` dans `$d`), parce qu'une session ne s'ouvre
pas depuis la session courante. Il y vérifie trois choses :
- elle donne la définition d'« essai » sans lire de fichier ;
- le lexique local arrive après les instructions et le lexique global ;
- un sous-agent lancé dans cette session (`Explore`, par exemple) connaît un terme global et un
  terme local : sa réponse va au journal, pour la limite ci-dessous.

### 4. Amorcer le lexique global

Relire `gabarit`, `list-dir` et `implementation-tracker` (SKILL.md et références) et proposer les
termes **un à un**, chacun avec sa définition d'une phrase et son lien. Seuls les termes validés
sont écrits. Candidats de départ, à confirmer à la lecture : *gabarit*, *semence*, *contrat*,
*estampille*, *répertoire-liste*, *élément*, *patron*, *chantier*, *brief*, *suivi*, *étape*,
*signal de dérive*, *hors-périmètre*, *registre*. Tout écart de vocabulaire constaté dans ces
skills est noté au journal, pour la dette ou la road-map, et **n'est pas corrigé** (hors-périmètre).

**Vérification** :
```bash
lexique liste; echo "sortie $?"   # 0, un terme global par ligne validée
git diff --stat master -- skills/gabarit skills/list-dir skills/implementation-tracker   # vide
```

## Limites connues, pour le journal

- Les sous-agents ne reçoivent pas `SessionStart` (voir l'en-tête de `hooks/outillage-rappel.sh`)
  et ne voient donc pas le lexique local. L'étape 3 vérifie ce qu'ils reçoivent réellement. La
  lacune est notée pour la dette, sans être traitée ici.
- Les `LEXIQUE.md` ne sont pas posés depuis une semence `gabarit`. Ils sont injectés bruts dans le
  contexte et n'ont ni champ ni section : un front matter y serait du bruit. Leur format est
  vérifié par `lexique liste`.

## Vérification de bout en bout

1. `pytest`, `ruff`, `basedpyright` et `check_pipeline.py` passent sans régression.
2. `grep -n '^@' CLAUDE.md` donne l'ordre attendu, et `lexique liste` sort en 0 sur le dépôt.
3. Ajouter à un lexique local un terme déjà global : `lexique liste --projet $d` sort en 1 et le
   nomme, et `lexique session` l'annonce en alerte avec un code 0.
4. Une session neuve dans un projet muni de `.claude/LEXIQUE.md` connaît ses termes.
